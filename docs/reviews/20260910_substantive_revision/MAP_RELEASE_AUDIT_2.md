## Public verification and numerical replay

`verify` uses standard-library code only, validating exact manifest/binding/file
inventories and checksums before importing scientific modules. Symlink, traversal,
unlisted-file and changed-body cases fail. Its strict pre-install mode rejects
extra files; runtime mode permits the named dependency/cache directories while
still verifying every declared payload. The included Python dependency closure
is the root initializer, precision-package initializer and unchanged precision
module; no acquisition or transport implementation is imported.

`check` verifies first, rejects cached scientific modules outside the supplied
root, prepends that root's `src`, and checks module origins after import and
numerical work. It calls **`qualify(load_proxy(root))` in memory** and the stored
report renderer, never the scientific create-once `build()` entry point. All
81 records, seeds, exact discrete fields, nulls and stopping decisions are
compared. It checks the retained report bytewise from the unchanged renderer
applied to the retained result. Final runtime inventory/binding and manifest
identity checks detect changes during replay. No scientific result is written.

The expected decision is explicitly `stop_inferential_proposal`, with neither R
nor output allocation selected; complete 81-cell/10,000-trial inventory is
required. Nothing in this adapter selects an alternative allocation or reopens
the failed collection proposal.

Finite scalar results retain absolute/relative tolerance 1e−10. **Support hashes
remain exact** and hash reconstructed floating-point array bytes. Therefore
