# 최종 수정본의 마지막 독립 평가

**후속 상태 (2026-09-15):** 이 평가는 아래 해시의 당시 원고에 해당한다.
이후 사용자가 마지막 수정과 저장소 정리를 요청하여
[후속 수정본](../final_update/README.md)이 만들어졌다. 아래 점수를 그 수정본에
적용하지 않으며, 평가 입력·원문·검증 기록은 그대로 보존한다.

사용자의 “마지막으로 한 번 더 평가해줘” 요청에 따라 최종 수정본을
Claude Code / Opus 5와 GPT-6 Astra / xhigh에 새로 평가받았다.
이번에는 **평가만 수행했으며 원고는 수정하거나 다시 빌드하지 않았다.**

평가 대상은 22쪽·초록 151단어·PDF 추출 텍스트 9,593단어인 최종본이다.
PDF SHA-256은
`4dd19f7d77d63eb17e7708d566607c3c001c7c8bc9afda84a5c297d93e7005b2`이며,
평가 당시 이전 작업의 최종 스냅샷과 원고가 모두 일치했다.

**두 평가자의 평균은 8.4375/10이다.** 네 항목을 각각 25%로 계산한
고정 version-1 기준이며, 산술평균과 0.25점 간격을 검증했다.

직전 `_03` 평가와 두 종합점수는 우연히 같다. 세부적으로는 Claude의
표현 점수가 8.00→8.25, 이해도가 8.25→8.00으로 바뀌었고, Astra의 표현이
8.75→9.00, 구성이 9.00→8.75로 바뀌었다. 다른 원고를 독립적으로 평가한
결과이므로 이를 수정 효과의 정밀한 측정으로 해석하지 않는다.

이 점수는 위 해시의 평가본에 해당한다. 이전 round 33의 세 평가자 목표와
99개 평가 기록을 대체하거나 그 평균에 합산하지 않는다.

## 평가의 공통점과 차이

두 평가자는 수식 전에 직관과 구체적인 예를 제시한 점, β와 D의 기준값을
반복해서 확인할 수 있는 점, 원본·생성 이미지와 대조 조건을 함께 보여 주는
그림 1, 주요 검정과 사후 진단의 구분을 강점으로 평가했다. 확인한 주요
수치 사이의 불일치나 수행하지 않은 인간 평가를 암시하는 표현은 보고하지 않았다.

공통으로 남긴 의견은 주의 문구와 해석의 반복이 후반부의 흐름을 느리게
한다는 것이다. 다만 각각의 제한이 하는 역할이 다르므로, 문구를 일괄
삭제하라는 뜻으로 받아들여서는 안 된다.

Astra의 주요 제안은 다음과 같다.

- §5.4에서 장면별 오차, 장면 평균 후 오차, 보정 후 오차가 서로 다른
  질문에 답한다는 점을 한 문장으로 먼저 정리하기.
- 초록에서 보정하는 대상이 “측정된 화가 대비 벡터”임을 더 직접적으로 표현하기.
- 결론에도 공통 변화의 기준이 artist-free 조건이며 유화 지시 효과가
  포함된다는 점을 유지하기. 본문 §5.2는 이를 올바르게 설명한다.

Claude는 여기에 본문에서 Appendix G의 모델 요청 설정·검증 한계로
연결되는 참조를 제안했다. 본문에는 이미 recorded configurations라는
범위 제한이 있지만, checkpoint attestation의 상세 한계와 직접 연결하는
것은 합리적인 가독성 제안이다.

**그림 2에 대한 판단은 갈렸다.** Astra는 overview/detail 구성이 유용하다고
평가했고, Claude는 overview가 조밀하고 detail이 작다는 점을 지적했다.
이는 독자의 시각적 선호와 읽는 방식에 따라 달라질 수 있는 편집 판단이다.

## 그대로 받아들이면 안 되는 Claude의 제안

아래는 평가자의 원문 의견과 별도로 확인한 사실관계다. 원래 점수나 의견은
수정하지 않았다.

1. **공통 변화를 전부 이름 효과로 표현하기:** 공통 named-minus-artist-free
   변화에는 유화 지시와 공통 명명 반응이 함께 포함된다. generic 변화보다
   크다는 사실만으로 전체를 이름 효과라고 부르거나 독립적인 기여율을
   분리할 수 없다. 두 성분 사이의 교차항도 존재한다.
2. **“2–4배 크다”에서 제곱 크기를 생략하기:** 1.96–4.14는 **제곱 크기**의
   비율이다. 크기 비율로 표현하면 약 1.40–2.03배다. 제안 문구처럼
   squared를 빼면 의미가 달라진다.
3. **β를 남은 between-name share라고 설명하기:** β는 reference 대비
   방향의 부호 있는 정규화 투영 계수다. 제곱 변화의 비율이 아니다.
   현재 원고는 두 개념을 구분하고 있다.
4. **overview를 하나로 합쳐도 정보 손실이 없다는 주장:** 각 모델의
   overview는 희미한 관측점뿐 아니라 네 화가의 평균과 연결선도 다르다.
   특히 Cézanne 정보는 M/S/P detail에 없으므로, 별도 보존 설계 없이
   하나로 줄이면 정보가 사라진다.
5. **모델 설정에 관한 제한이 본문에 전혀 없다는 주장:** §3.2에 이미
   recorded configurations라는 제한이 있다. “제한이 없다”는 진단은
   과장이고, Appendix G의 더 구체적인 설명을 본문과 연결하자는 제안이
   정확한 수준이다.

## 실행 및 기록 검증

- Claude는 새 UUID의 비영속 세션과 격리 폴더를 사용했다. 실제 CLI
  기록에서 Opus 5, 성공 종료, 22개 페이지 이미지 읽기 성공을 확인했다.
- Astra는 사용자 지정 `~/dev/openai-oauth` core client를 사용했다.
  실제 요청 및 완료 응답에서 `gpt-6-astra`와 `xhigh`를 확인했다.
  이전 응답 ID나 클라이언트 대화 이력은 사용하지 않았다.
- 양쪽에 같은 고정 기준·전체 텍스트·TeX·22쪽의 순서가 검증된 이미지를
  제공했다. 이전 점수·리뷰·목표 점수는 제공하지 않았다. Astra의 읽기
  범위는 모델의 보고이며, 입력 파일과 이미지 해시는 호스트가 검증했다.
  Astra에서 자동 문맥 압축이 1회 발생했다.
- Claude는 서문 뒤에 JSON을 출력하면서 `score_reasons`의 닫는 중괄호
  하나를 빠뜨렸다. 원문을 그대로 보존하고 JSON 저장에 필요한 구분자만
  복구했다. Astra의 `rubric_version: "1"`은 별도 정규화 파일에서 숫자
  `1`로 대응시켰다. 의견과 점수는 변경하지 않았고, 형식 복구를 위한
  추가 추론 요청도 하지 않았다.
- 평가 당시 원고와 모든 평가 입력이 이전 최종 스냅샷과 일치함을 확인했다.
