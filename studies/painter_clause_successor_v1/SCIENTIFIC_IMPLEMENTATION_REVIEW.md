## Collector and terminal evidence audit

I read the complete successor collection/workflow source and its tests. Live
admission requires explicit authorization or `httpx.MockTransport`, a committed
qualified source/configuration/freeze, exact assignment and runtime/proxy
identity, and the verified terminal predecessor. The predecessor gate follows
its real terminal hash chain and reads only the designated error-only refusal
body to confirm the original HTTP 400 moderation trigger; it never reads a
prospective feature result. The original C endpoint stays unavailable.

One-shot namespace locks, create-once paths and the single permitted run ID
prevent in-place resumption. Refusals and uncertain or unsupported outcomes are
not retried. Only qualified complete technical errors permit one same-payload
retry, within eight retries and 104 total attempt intents. Blocks complete
before the next starts; at most two workers run. Admission stops for the
specified completion-window, deadline, disk and contract failures, then drains
workers and performs final source/proxy checks. The identity-failure event is
retained even after an earlier non-identity halt, so a later interruption cannot
be hidden by the first stopping reason.

Terminal replay recomputes attempt/terminal pairing, selected first valid
outputs, exact slot order, retry/posted totals, identity from terminal/operator
records, duration eligibility and ledger budget. Every allocated slot remains
accounted for after stopping. Measurement is terminal-only and retains failed
slots in every pipeline; replay binds measurements, JSON analysis, report and
measurement-start marker to the collection receipt.

The inherited HTTP timeout is an inactivity timeout, not a wall-clock guarantee.
The five-minute admission reserve therefore cannot prove timely drainage. The
actual elapsed-time gate correctly withholds inference when drainage exceeds
24 hours. This operational limit is disclosed rather than treated as a defect
that changes the estimand or invites replacement.
