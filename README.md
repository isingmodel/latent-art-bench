# LatentArtBench

LatentArtBench is a research codebase for testing, for one exact model and one R0a-frozen
24-template common-content prompt frame, whether registered painter-name requests first meet
availability and content-adherence requirements and whether their technically analyzable,
near-copy-excluded outputs reproduce the content-standardized feature distribution in the
corresponding painter's R0a-randomized sealed-confirmation population of eligible digital painting
surrogates. It separates absolute target fit, close-painter specificity, distribution coverage,
prompt effects, copying, availability, and evaluator sensitivity.

> **Reboot status (2026-09-02):** Pilots 0–3 and the real-only Painter Features v1 protocol are
> historical evidence. The active study is
> [Painter Feature Generation v1](studies/painter_feature_generation_v1/PROTOCOL.md), version 1.7. Its protocol
> is complete as a prospective plan, but the four-painter corpus is currently NO-GO. Its R0a census,
> R1a simulation, R0b complete-qualification release, R1b qualification, and G0 generator freeze are
> not complete;
> no new generation or fidelity result exists. See [current status](docs/STATUS.md).

The active design has one `outdoor_place_landscape` domain and four broad scene groups; the former
six narrow submotifs remain nonbinding diagnostics. R0a must acquire, adjudicate, and analyze every
work in a minimum 1,440-work internal finite frame: 360 per painter, split by one frozen painter-level
random permutation into 72 development, 108 method-qualification, and at least 180 sealed-
confirmation works per painter (288, 432, and at least 720 overall). Optional external replication
adds a complete 96-work census per painter, or 384 works, so the acquired and analyzed total becomes
at least 1,824. A separate auxiliary same-work independent-capture census contains every eligible
work in its frozen frame, must include at least 32 physical works—at least eight per painter and two
independent captures per work—and is outside every internal and external total.

Before any active content label is read, R0a hashes all 12 byte-exact candidate complete prompt
frames: every artist-free and named-placeholder string, punctuation, language, negative prompt,
condition insertion point, painter-name substitution table, scene label, five content values, and
render behavior for all 24 templates. No later stage, including G0, may rewrite them. After painter-
level population assignment, R0a selects one frame using only the three nonredundant broad-scene
proportions and exactly five predeclared binary visible-property means. The selected equal-weight
frame gives every named condition and shared artist-free control
the same repetition count `R` in every template; unequal or supplementary unpaired primary blocks
are forbidden. With four painters, the active request count is `120R`. The former `R=16`,
1,920-request scenario is retired because it cannot clear the boundary-safe availability gate even
with perfect returns. Even the impossible best case (`alpha_e=.05`, six templates per scene group,
threshold .90, and every repetition its own auditable independent unit) requires `R>=25`, or at
least 3,000 requests; the actual Bonferroni allocation and
whole-decision simulation require a larger, still-unfrozen `R`. Deterministic seed lists are
used only for a fixed deterministic local execution map: they are independent template-specific IID
uniform draws with replacement, and chance duplicates are retained. An opaque or remote endpoint
instead uses `C` equal-size common-shock units, each with `L` complete balanced waves containing
every template×named/control condition, so `R=C*L`. For every complete real development, qualification, confirmation, and
registered-external population,
R0a freezes the jointly feasible full-population entropy projection `q*` to the selected common
target. `q*` is the primary real-population measure, is subject to joint convex-hull, weight-cap, and
effective-sample-size gates, and is never refit; the uniform complete population is a mandatory
sensitivity. One common transform uses the weighted median and IQR of the equal-painter mixture of
the four `q*`-weighted development populations and is then fixed for all real, control, and generated
vectors. A separately frozen, binding realized-content entropy projection uses blind output labels,
the same support gates, and cannot rescue a failed intention-to-prompt result. The design does not
claim exact joint-profile matching.

Current discovery evidence comprises 3,190 **Wikidata painting-item candidates** and a separate
traceable live-item audit of 43 all-content official-source metadata candidates. The 43-item record
is traceable evidence of the live pages observed, not a reproducible as-of-date source snapshot.
Neither count is a set of admitted outdoor-place works. Active-study admission, downloaded-image,
registered-generation, generated-output, and result counts are all zero, so R0a remains **NO-GO**.
Internal GO requires 360 fully eligible candidates per painter and at least 24 in every broad scene
group. Registering the optional external plan requires another 96 unopened-source candidates per
painter and at least eight per broad scene group, or 456 combined per painter.

Eligibility coding is real pixel exposure: two independent coders use only frozen derivatives with
long side at most 512 pixels and painter, title, institution, accession, and source masked. Those
derivatives and adjudication records are firewalled from feature, method, and generation analysts;
before adjudication, exact three-way visual-eligibility agreement must be at least 0.90 per painter
and each coder's `ambiguous_multiple` share at most 0.10. On the union-eligible denominator, raw
agreement must be at least 0.85 for the broad scene label and each five-property three-state contrast;
the 0.85 gate is repeated in every assigned internal and registered-external population, and each
coder's season/illumination/depth indeterminate fraction must be at most 0.20 in every applicable
denominator. Any failure is R0a NO-GO and later adjudication cannot erase it. In G1b, every sealed-
confirmation and technically analyzable generated image is independently double-coded; raw labels
and the same 0.85/0.20 receipts are sealed before a third blinded adjudicator creates the consensus.
A failed G1b receipt makes the affected adherence, realized-content, and feature-reproduction
endpoint inconclusive. Analysis-resolution qualification/final files remain inaccessible, and final-
reference files stay sealed through G1a. The painter-level permutation assigns exposure roles but
does not create later probability subsamples: every work in each released population is measured,
and R0b opens the whole 108-work-per-painter qualification census without adding to or redefining the
R0a frame. Primary energy uses an exact `q*`-weighted real-census summation inside the generated–real
term, an exact real–real finite component, and an equal-template generated U-statistic; generator
expectations remain estimated from registered draws. Under a fixed deterministic local map,
continuous uncertainty resamples whole seed-
condition vectors within template; for an opaque/remote endpoint it resamples only whole balanced
common-shock units, each carrying all waves and template×condition outcomes. The same G0 independence
partition governs rate and continuous inference while all real censuses and weights stay fixed; there
is no real-work bootstrap,
inverse-probability estimator, or active SRSWOR design. Source is not a sampling stratum: source
robustness is binding, the primary result is specific to the observed source mixture, and exact
common source×scene-group comparisons are mandatory diagnostics only where the frozen frame
supports them. The internal frame and each assigned internal population require at least four
holding/capture groups per painter. The frame caps each group's unweighted share at 30%; each assigned
population caps both unweighted and `q*` shares at 30%. Multi-source frame scenes have an unweighted
70% cap; assigned-population scenes cap both unweighted and scene-conditional `q*` shares at 70%,
while registered external populations require two unopened groups and both overall shares at or
below 70%. No full-frame `q*` exists. The binding source-shift functional is the RMS, across the one
commonly scaled coordinate family, of each source group's exact `q*`-weighted median shift from its
complement; it is compared with the auxiliary-census disturbance bound and repeated under uniform weights. Continuous endpoints
use 9,999 generator-vector replicates. Availability, adherence, and copy rates instead use a
separately alpha-allocated Bonferroni weighted-Hoeffding construction with conservative ratio bounds;
for a full endpoint, `M_rate` counts four one-sided events—`A` lower, `A` upper, `J` lower, and `K`
upper. For rates the Hoeffding radius uses `sum_c W_c^2`; request IDs or timestamps do not establish
independence for a remote service. Plausible provider episodes, batches, backend revisions,
moderation states, outages, retry cascades, and other common shocks stay together. If a shock crosses
the frozen boundaries, a balanced unit cannot be retained with failures, or the partition cannot
align with the fixed-template continuous resampler, both affected rate and continuous endpoints are
ineligible or inconclusive. They are not empirical-bootstrap intervals. Any
nonstructural zero bootstrap variance is inconclusive, not zero-width certainty.

No Pilot 3 development A-vectors, repeat probes, external-holdout access, image-generation
transport qualification, or analytic generation exist.

## Development setup

The project declares Python 3.9 or newer and requires `uv`; install `uv` with your platform's
package manager or its official installer before setup. The complete learned feature stack is
large. This reboot baseline was validated with CPython 3.13.11 on macOS arm64.

```bash
uv sync --locked --extra dev --extra learned
uv run --locked ruff check .
uv run --locked pytest -q -m "not live"
```

At the reboot baseline, Ruff passes and the offline suite contains 490 passing tests. The
standard command excludes the registered `live` marker. Tests use fixtures and injected
transports; they do not authorize live image, museum, browser, or API requests.

The historical `pilot2 verify` and planning-era `pilot3 verify` commands are not general
repository health checks on current `main`. Both correctly reject current implementation
drift from their older hash-bound closures. Do not regenerate a frozen bundle merely to make
one of those commands green.

## Artifact model

Git tracks source, tests, configuration, compact evidence, durable Pilot 2 attempt receipts,
and downsampled Pilot 2 visual-QC sheets. It intentionally ignores copyrighted artwork,
generated full-resolution images, model weights, source checkouts, derived images, feature
vectors, caches, and runtime locks.

Some ignored files are unique local evidence required by historical offline verification.
Never run broad cleanup commands such as `git clean -xfd`, and never recursively remove
`artifacts/`, `data/`, or `outputs/`. Follow the [artifact retention policy](docs/ARTIFACTS.md).

## Reboot rule

Treat Pilots 0–3 and hash-bound Painter Features v1 records as immutable study history. The active
reboot may reuse tested primitives and development data only under the new protocol's exposure and
claim rules. Network acquisition, feature extraction, and generation remain closed until the
corresponding R0a/R1a/R0b/R1b or G0 freeze is reviewed and committed. Use only the
[Painter Feature Generation v1 protocol](studies/painter_feature_generation_v1/PROTOCOL.md) as the
current plan. G1a must seal every generation attempt and output hash while the final real reference
remains unopened; only G1b may open that reference and run confirmation.
